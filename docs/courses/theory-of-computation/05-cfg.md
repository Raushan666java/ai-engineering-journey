# Chapter 5: Context-Free Grammars

## Learning Objectives

By the end of this chapter, you should be able to: define a context-free grammar formally; construct derivations (leftmost and rightmost) and parse trees; identify and eliminate ambiguity in grammars; design CFGs for common programming language constructs; transform grammars into normal forms (Chomsky and Greibach).

## Theory

### Formal Definition

A **context-free grammar** (CFG) is a 4-tuple

$$G = (V, \Sigma, R, S)$$

where:

- $V$ is a finite set of **variables** (nonterminals)
- $\Sigma$ is a finite set of **terminals** (disjoint from $V$)
- $R \subseteq V \times (V \cup \Sigma)^*$ is a finite set of **productions** (rules)
- $S \in V$ is the **start symbol**

Each production $(A, \alpha)$ is written $A \to \alpha$. The grammar is called "context-free" because the production $A \to \alpha$ can be applied to the variable $A$ regardless of its surrounding context.

### Derivations

If $u, v \in (V \cup \Sigma)^*$ and $A \to \gamma \in R$, then we write $uAv \Rightarrow u\gamma v$ (one step of derivation). The reflexive transitive closure is $\Rightarrow^*$.

A **leftmost derivation** always expands the leftmost variable at each step. A **rightmost derivation** always expands the rightmost variable.

The language generated by $G$ is:

$$L(G) = \{ w \in \Sigma^* \mid S \Rightarrow^* w \}$$

A language $L$ is **context-free** if there exists a CFG $G$ such that $L(G) = L$.

### Parse Trees

A parse tree is a rooted ordered tree where:
- Interior nodes are labeled with variables
- Leaf nodes are labeled with terminals or $\epsilon$
- The root is labeled $S$
- If an interior node is labeled $A$ and its children are $X_1, \ldots, X_k$, then $A \to X_1 \cdots X_k \in R$

Derivations correspond to traversals of parse trees. Multiple derivations may correspond to the same parse tree. A grammar is **ambiguous** if some string has two distinct parse trees (or equivalently, two distinct leftmost derivations).

### Ambiguity and Its Elimination

Ambiguity arises when the grammar allows multiple structural interpretations of the same string. This is problematic for compiler design because a program should have exactly one meaning.

**Example**: The grammar $E \to E + E \mid E \times E \mid (E) \mid \text{id}$ is ambiguous for $a + b \times c$: one parse tree groups $(a + b) \times c$, another groups $a + (b \times c)$.

To eliminate ambiguity, we introduce precedence and associativity:

$E \to E + T \mid T$
$T \to T \times F \mid F$
$F \to (E) \mid \text{id}$

Here $+$ is left-associative and $\times$ has higher precedence.

### CFG Design

Common strategies for designing CFGs:

1. **Concatenation**: To generate $L_1 L_2$, use $S \to S_1 S_2$ where $S_1$ generates $L_1$ and $S_2$ generates $L_2$.
2. **Union**: To generate $L_1 \cup L_2$, use $S \to S_1 \mid S_2$.
3. **Kleene star**: To generate $L^*$, use $S \to S_1 S \mid \epsilon$.
4. **Counting**: For languages requiring counting (like $0^n 1^n$), use symmetric productions.

### Chomsky Normal Form

A CFG is in **Chomsky Normal Form (CNF)** if every production is of the form:

- $A \to BC$ where $A, B, C \in V$ and $B, C \neq S$
- $A \to a$ where $a \in \Sigma$
- $S \to \epsilon$ is allowed only if $\epsilon \in L(G)$

**Theorem 5.1**: Every CFG can be converted to CNF.

**Conversion steps**:
1. Add new start variable $S_0$ with $S_0 \to S$.
2. Eliminate $\epsilon$-productions ($A \to \epsilon$).
3. Eliminate unit productions ($A \to B$).
4. Replace terminals in long productions: $A \to uBC$ becomes $A \to UBC$, $U \to u$.
5. Break long productions into binary: $A \to B_1 B_2 \cdots B_k$ becomes $A \to B_1 A_1$, $A_1 \to B_2 A_2$, etc.

### Greibach Normal Form

A CFG is in **Greibach Normal Form (GNF)** if every production is of the form $A \to a\gamma$ where $a \in \Sigma$ and $\gamma \in V^*$ (each production starts with a terminal followed by zero or more variables). Every CFG can be converted to GNF.

## Examples

### Example 1: CFG for Balanced Parentheses

Design a CFG generating $\{ w \in \{(\), )\}^* \mid w \text{ has balanced parentheses} \}$.

$S \to SS \mid (S) \mid \epsilon$

This grammar is ambiguous. For $()()$, we have two parse trees: $(S)(S)$ and $S(S)$ depending on whether we combine them as left then right or outer-inner.

A non-ambiguous version: $S \to (S)S \mid \epsilon$. This forces each opening parenthesis to match with a closing one before any following pairs.

### Example 2: CFG for $0^n 1^n$

$S \to 0 S 1 \mid \epsilon$

Derivation of $0^3 1^3$:
$S \Rightarrow 0 S 1 \Rightarrow 0 0 S 1 1 \Rightarrow 0 0 0 S 1 1 1 \Rightarrow 0 0 0 1 1 1$

### Example 3: CFG for Arithmetic Expressions

$E \to E + T \mid T$
$T \to T \times F \mid F$
$F \to (E) \mid \text{id}$

Leftmost derivation of $\text{id} + \text{id} \times \text{id}$:
$E \Rightarrow E + T \Rightarrow T + T \Rightarrow F + T \Rightarrow \text{id} + T \Rightarrow \text{id} + T \times F \Rightarrow \text{id} + F \times F \Rightarrow \text{id} + \text{id} \times F \Rightarrow \text{id} + \text{id} \times \text{id}$

### Example 4: CNF Conversion

Convert $S \to aSb \mid \epsilon$ to CNF.

1. Add $S_0 \to S$.
2. Eliminate $\epsilon$: $S \to aSb \mid ab$, $S_0 \to aSb \mid ab \mid \epsilon$.
3. Introduce $A \to a$, $B \to b$.
   $S_0 \to ASB \mid AB \mid \epsilon$
   $S \to ASB \mid AB$
   $A \to a$
   $B \to b$
4. Break $S_0 \to ASB$:
   $S_0 \to A C_1$, $C_1 \to SB$
   $S \to A C_1$, $C_1 \to SB$

Final CNF: $S_0 \to A C_1 \mid AB \mid \epsilon$, $S \to A C_1 \mid AB$, $C_1 \to SB$, $A \to a$, $B \to b$.

## Summary

- CFGs consist of variables, terminals, productions, and a start symbol.
- Derivations replace variables with right-hand sides of productions.
- Parse trees represent the hierarchical structure of derivations.
- Ambiguity means multiple parse trees exist for some string; it can often be eliminated.
- Normal forms (CNF, GNF) standardize grammar structure for algorithmic processing.
- CFGs are central to programming language syntax definition (BNF, EBNF).
