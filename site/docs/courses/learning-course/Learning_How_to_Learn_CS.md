# Learning How to Learn — Computer Science (Single Page) 🔧

**Purpose:** A focused, actionable one-page course to become a highly effective Computer Science student — better grades, stronger projects, faster mastery of concepts, and interview-readiness.

---

## Outcome Goals

- **Understand** core CS concepts (algorithms, systems, data structures, OS, networks, databases).
- **Apply** knowledge to projects, labs, and interviews.
- **Retain** knowledge long-term using active methods.
- **Iterate** on learning with measurable progress (projects, solved problems, notes).

---

## Core Principles

- **Active Recall** — Test yourself before re-reading.
- **Spaced Repetition** — Schedule reviews to move knowledge to long-term memory.
- **Deliberate Practice** — Tackle just-out-of-reach problems with focused feedback.
- **Interleaving** — Mix topics to improve transfer.
- **Feynman Technique** — Explain concepts simply; identify gaps.

> Tip: Replace passive reading with a 20–30 minute active session: try recall, solve, then confirm.

---

## Learning Framework — 4 Stages

A compact, repeatable cycle you can apply to every topic or project. Use these stages intentionally and measure progress at each step.

### 1) Information Acquisition 🔍

- SQ3R (Survey, Question, Read, Recite, Review): skim first, turn headings into questions, read to answer them, recite key points aloud, then review summaries.
- Active reading: highlight sparingly, write 1–2 sentence summaries per section, convert diagrams into steps or pseudocode.
- Strategic search: use targeted queries, curated syllabi (MIT OCW, CS50), and canonical implementations to focus learning resources.
- Practical experimentation: implement minimal examples, write tests, use REPLs and sandboxes to observe behavior.
- CS examples: read an algorithm paper, implement the core algorithm in 30–60 minutes, compare behavior on edge cases.

**Acquisition checklist:** pick source → survey → generate 3 questions → implement a tiny example.

### 2) Storage 💾

- Note-taking: use concise Markdown notes or Zettelkasten-style atomic notes with links and tags; keep one idea per note.
- Chunking: split complex ideas (e.g., virtual memory) into manageable chunks: concept, mechanism, code, failure modes.
- Spaced repetition: convert facts, definitions, and key code snippets into Anki cards; schedule reviews based on recall difficulty.
- CS examples: create card(s) for algorithm invariants, common pitfalls, and key APIs.

**Storage checklist:** write 1–2 atomic notes → tag and link → create/update 3 Anki cards.

### 3) Retrieval 🧠

- Systematic review: weekly review session that replays summaries, runs spaced-repetition cards, and revisits notes.
- Self-quizzing: answer your own questions, re-derive proofs, write code from memory, and perform whiteboard-style explanations.
- Practice tests: simulate exam conditions—timed coding problems, mock interviews, or project bug hunts with automated tests.
- CS examples: solve 2–3 problems with no internet, reproduce a project's critical function from scratch.

**Retrieval checklist:** weekly quiz → 2 timed problems → write one explanation/note from memory.

### 4) Metacognition 🔁

- Self-reflection: keep a short learning journal—what worked, what failed, and why. Track confidence and time spent per topic.
- Goal setting: set measurable micro-goals (e.g., "get 80% of medium LeetCode problems in 45 minutes") and review them monthly.
- Continuous integration: adapt resources and schedules based on outcomes; treat learning like iterative software: plan → implement → test → deploy improvements.
- CS examples: after a project sprint, run a post-mortem: what tests failed, what knowledge gaps caused the bug, update notes and cards.

**Metacognition checklist:** weekly retrospective entry → adjust next week's goals → update SRS and project backlog.

### Integrating the Framework ✨

- Map sessions: use Concept Sessions for Acquisition, Review & SRS for Storage, Problem-solving for Retrieval, and the Weekly Retrospective for Metacognition.
- Quick habit: at the end of every session, spend 3–5 minutes noting which stage you completed and one next action.

## Weekly Structure

- 3× Deep Coding Sessions (90–120 min) — implement, debug, test
- 2× Concept Sessions (60 min) — read + Feynman explain
- 2× Problem-solving (45–60 min) — LeetCode/CS problems + solution write-up
- 1× Project/Integration session (120–180 min) — add feature or fix bug
- 1× Review & SRS update (30–45 min) — flashcards, notes, retrospective

## Coding → Concept & Learning Styles

Connect code to concept efficiently and adapt study methods to your learning style.

### Coding → Concept (practical)

- Run & Trace: execute an example and step through with logs or a debugger to understand control flow and state changes.
- Pseudocode & Diagrams: translate code paths into simplified pseudocode, sequence diagrams, or flowcharts to reveal abstractions.
- Abstraction Ladder: map implementation ↔ data structures ↔ invariants/algorithms ↔ proofs/theory.
- Mini-experiments: change inputs, add instrumentation, and benchmark to see how behavior changes under edge cases.
- Teach & Document: write a 2–4 sentence explanation and create an atomic note to solidify connections.

**Coding→Concept checklist:** run & trace → draw a diagram → write a short explanation → add/update one atomic note.

### Learning Styles — CS-focused strategies

- Visual learners: use diagrams, color-coded code annotations, sequence charts, and whiteboard sketches.
- Auditory learners: explain concepts aloud, record short verbal summaries, and do pair-programming talk-throughs.
- Reading/Writing learners: keep structured Markdown notes, write step-by-step guides, and create detailed flashcards.
- Kinesthetic learners: prefer building small experiments, using REPLs, and hands-on projects to discover behaviors.
- Social learners: learn via study groups, code reviews, and teaching sessions.
- Solitary learners: benefit from focused solo sessions, journaling, and timed practice tests.

**Tip:** Combine styles — draw a diagram (visual), explain it aloud (auditory), implement it (kinesthetic), then write a concise note (reading/writing).

**Quick checklist after each session:** run & trace → diagram → atomic note → 1 Anki card → 5-min verbal explanation.
