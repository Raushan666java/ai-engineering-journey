# Module 1: Software Development Life Cycle (SDLC) Models
## Week 1-2: Foundation of Software Engineering

## 📋 Module Overview
This module covers the core concepts of software development processes and methodologies. You'll learn about various SDLC models, their applications, advantages, and limitations. By the end of this module, you'll be able to select appropriate SDLC models for different project scenarios.

## 🎯 Learning Objectives
- Understand the history and evolution of software engineering
- Compare and contrast different SDLC models
- Apply appropriate SDLC models to various project scenarios
- Create project plans using different methodologies
- Analyze case studies of real-world software development projects

### 1.2 SDLC Models In-Depth

#### 1.2.1 Waterfall Model
- Origin and history
- Phases in detail:
  - Requirements analysis and specification
  - System and software design
  - Implementation and unit testing
  - Integration and system testing
  - Deployment and maintenance
- Documentation requirements at each phase
- Advantages:
  - Clear structure and milestones
  - Easy to understand and manage
  - Well-defined deliverables
- Disadvantages:
  - Limited flexibility for changes
  - Late testing and risk discovery
  - Customer feedback comes late
- When to use:
  - Well-understood requirements
  - Stable product definition
  - Short-duration projects
  - Regulatory environments
- Case Study: NASA Space Shuttle software development

#### 1.2.2 Agile Methodology
- Agile Manifesto (2001) in detail:
  - Individuals and interactions over processes and tools
  - Working software over comprehensive documentation
  - Customer collaboration over contract negotiation
  - Responding to change over following a plan
- 12 Principles of Agile Software
- Core Agile values and philosophy
- Iterative and incremental development approach
- Continuous delivery and integration
- Adaptive planning and evolutionary development
- Rapid and flexible response to change
- Customer involvement and feedback
- Popular Agile frameworks overview:
  - Scrum
  - XP (Extreme Programming)
  - Lean Software Development
  - Crystal
  - Feature-Driven Development (FDD)
- Case Study: Spotify engineering culture

#### 1.2.3 Scrum Framework
- Scrum Roles:
  - Product Owner: responsibilities and daily activities
  - Scrum Master: servant leadership model
  - Development Team: self-organization and cross-functionality
- Scrum Artifacts:
  - Product Backlog: creation and refinement
  - Sprint Backlog: sprint planning and commitment
  - Increment: definition of "Done"
  - Burndown charts and information radiators
- Scrum Events:
  - Sprint Planning: time-boxing and objectives
  - Daily Scrum: structure and purpose
  - Sprint Review: demonstration and feedback
  - Sprint Retrospective: continuous improvement
  - Sprint: time-boxed iteration (1-4 weeks)
- Estimation in Scrum:
  - Story points vs. hours
  - Planning Poker technique
  - Velocity calculation and sprint capacity
- Scaling Scrum for larger projects
- Common Scrum pitfalls and solutions
- Case Study: Scrum implementation at Microsoft

#### 1.2.4 Kanban Method
- History and Toyota Production System origins
- Core principles:
  - Visualize the workflow
  - Limit Work In Progress (WIP)
  - Manage flow
  - Make process policies explicit
  - Implement feedback loops
  - Improve collaboratively, evolve experimentally
- Kanban board components:
  - Columns and swim lanes
  - Cards and tickets
  - WIP limits
  - Entry and exit criteria
- Metrics in Kanban:
  - Lead time and cycle time
  - Throughput
  - Cumulative Flow Diagrams
  - Bottleneck identification
- Differences between Kanban and Scrum
- Implementing Kanban in development teams
- Case Study: Kanban at Siemens Healthcare

#### 1.2.5 Other SDLC Models
- Spiral Model:
  - Risk-driven approach
  - Four quadrants (Planning, Risk Analysis, Engineering, Evaluation)
  - When to use spiral model
  - Case study: Large defense projects
- V-Model:
  - Verification and validation model
  - Test planning in parallel with development phases
  - Extensions to V-Model
  - When to use V-Model
  - Case study: Medical device development
- Incremental Model:
  - Building and delivering in increments
  - Advantages and disadvantages
  - When to use incremental model
- RAD (Rapid Application Development):
  - Prototyping approach
  - JAD (Joint Application Development) sessions
  - When to use RAD
  - Case study: Business application development
- DevOps:
  - Integration of development and operations
  - Continuous integration and continuous deployment
  - Infrastructure as code
  - Case study: Amazon's deployment process

### 1.3 Comparative Analysis of SDLC Models
- Selection criteria for SDLC models:
  - Project size and complexity
  - Requirements stability
  - Time-to-market constraints
  - Team size and distribution
  - Regulatory requirements
  - Customer involvement
- Handling requirements changes in different models
- Risk management approaches
- Documentation requirements comparison
- Team structure and dynamics
- Quality assurance integration
- Cost and schedule implications
- Hybrid approaches:
  - Water-Scrum-Fall
  - Disciplined Agile Delivery (DAD)
  - Scaled Agile Framework (SAFe)
