# Structural Design Patterns
## Comprehensive Implementation Guide

## 📋 Introduction to Structural Design Patterns

Structural design patterns explain how to assemble objects and classes into larger structures while keeping these structures flexible and efficient. These patterns deal with object composition, creating relationships between entities.

Structural patterns help ensure that if one part of a system changes, the entire structure doesn't need to change. They identify simple ways to realize relationships among entities and help compose objects to obtain new functionality.

### Why Structural Patterns Matter

1. **Composition Over Inheritance**: They promote object composition instead of class inheritance
2. **Flexibility**: They make it easier to change the composition at runtime
3. **Decoupling**: They reduce dependencies between components
4. **Code Reuse**: They enable reusing existing code in new contexts
5. **Interface Adaptation**: They help different interfaces work together

## 🔑 Core Structural Patterns

### 1. Adapter Pattern

#### Intent
Convert the interface of a class into another interface clients expect. Adapter lets classes work together that couldn't otherwise because of incompatible interfaces.

#### Real-world Analogy
Power adapters for different countries: A US device can work in Europe with the right adapter that converts between different plug formats.

#### Structure
```
+----------+       +----------+       +----------+
|  Client  |------>| Adapter  |------>| Adaptee  |
+----------+       +----------+       +----------+
| request()|       | request()|       |specificRequest()|
+----------+       +----------+       +----------+
```

#### Implementation in Java
```java
// Target interface - what the client expects
interface MediaPlayer {
    void play(String audioType, String fileName);
}

// Adaptee - existing class with incompatible interface
class AdvancedMediaPlayer {
    void playVlc(String fileName) {
        System.out.println("Playing vlc file: " + fileName);
    }
    
    void playMp4(String fileName) {
        System.out.println("Playing mp4 file: " + fileName);
    }
}

// Adapter - makes AdvancedMediaPlayer compatible with MediaPlayer
class MediaAdapter implements MediaPlayer {
    private AdvancedMediaPlayer advancedPlayer;
    
    public MediaAdapter(String audioType) {
        if (audioType.equalsIgnoreCase("vlc") || audioType.equalsIgnoreCase("mp4")) {
            advancedPlayer = new AdvancedMediaPlayer();
        }
    }
    
    @Override
    public void play(String audioType, String fileName) {
        if (audioType.equalsIgnoreCase("vlc")) {
            advancedPlayer.playVlc(fileName);
        } else if (audioType.equalsIgnoreCase("mp4")) {
            advancedPlayer.playMp4(fileName);
        }
    }
}

// Concrete implementation of MediaPlayer
class AudioPlayer implements MediaPlayer {
    private MediaAdapter mediaAdapter;
    
    @Override
    public void play(String audioType, String fileName) {
        // Built-in support for mp3
        if (audioType.equalsIgnoreCase("mp3")) {
            System.out.println("Playing mp3 file: " + fileName);
        }
        // Use adapter for other formats
        else if (audioType.equalsIgnoreCase("vlc") || audioType.equalsIgnoreCase("mp4")) {
            mediaAdapter = new MediaAdapter(audioType);
            mediaAdapter.play(audioType, fileName);
        } else {
            System.out.println("Invalid media. " + audioType + " format not supported");
        }
    }
}

// Usage
public class AdapterDemo {
    public static void main(String[] args) {
        AudioPlayer audioPlayer = new AudioPlayer();
        
        audioPlayer.play("mp3", "beyond_the_horizon.mp3");
        audioPlayer.play("mp4", "alone.mp4");
        audioPlayer.play("vlc", "far_far_away.vlc");
        audioPlayer.play("avi", "mind_me.avi");
    }
}
```

```python
from abc import ABC, abstractmethod

# Target interface
class Target(ABC):
    @abstractmethod
    def request(self) -> str:
        pass

# Adaptee - class with incompatible interface
class Adaptee:
    def specific_request(self) -> str:
        return ".eetpadA eht fo roivaheb laicepS"

# Adapter
class Adapter(Target):
    def __init__(self, adaptee: Adaptee) -> None:
        self._adaptee = adaptee
    
    def request(self) -> str:
        # Adapt the incompatible interface
        return f"Adapter: (TRANSLATED) {self._adaptee.specific_request()[::-1]}"

# Client code
def client_code(target: Target) -> None:
    print(target.request(), end="")

if __name__ == "__main__":
    print("Client: I can work just fine with the Target objects:")
    target = Target()  # This would need a concrete implementation
    # client_code(target)
    
    adaptee = Adaptee()
    print("Client: The Adaptee class has a weird interface. See, I don't understand it:")
    print(f"Adaptee: {adaptee.specific_request()}", end="\n\n")
    
    print("Client: But I can work with it via the Adapter:")
    adapter = Adapter(adaptee)
    client_code(adapter)
```

### 2. Bridge Pattern

#### Intent
Separate an abstraction from its implementation so that the two can vary independently.

#### Real-world Analogy
Remote control and devices: A universal remote (abstraction) can work with different devices (implementations) like TV, stereo, or DVD player.

#### Structure
```
+-------------+       +----------------+
| Abstraction |------>| Implementation |
+-------------+       +----------------+
| operation() |       | operationImpl()|
+-------------+       +----------------+
      ^                        ^
      |                        |
+-------------+       +----------------+
|RefinedAbstraction|  |ConcreteImplementation|
+-------------+       +----------------+
| operation() |       | operationImpl()|
+-------------+       +----------------+
```

### 3. Composite Pattern

#### Intent
Compose objects into tree structures to represent part-whole hierarchies. Composite lets clients treat individual objects and compositions of objects uniformly.

#### Real-world Analogy
Military hierarchy: Individual soldiers and units (groups of soldiers) can both receive and execute orders in the same way.

#### Structure
```
+------------+
|  Component |
+------------+
| operation()|
| add()      |
| remove()   |
+------------+
      ^
      |
+-----+-----+
|           |
+------+  +----------+
| Leaf |  | Composite|
+------+  +----------+
|operation()| operation()|
+------+  | add()    |
          | remove() |
          +----------+
```

#### Implementation in JavaScript
```javascript
// Component interface
class FileSystemItem {
    constructor(name) {
        this.name = name;
    }
    
    // Abstract methods to be implemented by subclasses
    getSize() {
        throw new Error("Method must be implemented by subclass");
    }
    
    print(indent = "") {
        throw new Error("Method must be implemented by subclass");
    }
    
    add(item) {
        throw new Error("Cannot add to a leaf");
    }
    
    remove(item) {
        throw new Error("Cannot remove from a leaf");
    }
    
    getChild(index) {
        throw new Error("No children available");
    }
}

// Leaf - represents individual files
class File extends FileSystemItem {
    constructor(name, size) {
        super(name);
        this.size = size;
    }
    
    getSize() {
        return this.size;
    }
    
    print(indent = "") {
        console.log(`${indent}📄 ${this.name} (${this.size} KB)`);
    }
}

// Composite - represents directories that can contain files and other directories
class Directory extends FileSystemItem {
    constructor(name) {
        super(name);
        this.children = [];
    }
    
    add(item) {
        this.children.push(item);
        return this;
    }
    
    remove(item) {
        const index = this.children.indexOf(item);
        if (index !== -1) {
            this.children.splice(index, 1);
        }
        return this;
    }
    
    getChild(index) {
        return this.children[index];
    }
    
    getSize() {
        return this.children.reduce((total, child) => total + child.getSize(), 0);
    }
    
    print(indent = "") {
        console.log(`${indent}📁 ${this.name}/ (${this.getSize()} KB total)`);
        this.children.forEach(child => {
            child.print(indent + "  ");
        });
    }
}

// Usage
const root = new Directory("root");
const home = new Directory("home");
const user = new Directory("user");

const documents = new Directory("Documents");
const downloads = new Directory("Downloads");

// Create some files
const resume = new File("resume.pdf", 150);
const photo = new File("photo.jpg", 2500);
const music = new File("song.mp3", 5000);
const video = new File("movie.mp4", 750000);

// Build the file system structure
documents.add(resume);
downloads.add(photo).add(music).add(video);

user.add(documents).add(downloads);
home.add(user);
root.add(home);

// Add some system files to root
const systemFile = new File("system.log", 50);
root.add(systemFile);

// Print the entire file system
console.log("File System Structure:");
root.print();

console.log(`\nTotal size: ${root.getSize()} KB`);
```

#### Implementation in Python
```python
from abc import ABC, abstractmethod
from typing import List

# Component interface
class Graphic(ABC):
    @abstractmethod
    def draw(self) -> None:
        pass
    
    @abstractmethod
    def move(self, x: int, y: int) -> None:
        pass

# Leaf components
class Dot(Graphic):
    def __init__(self, x: int, y: int):
        self._x = x
        self._y = y
    
    def draw(self) -> None:
        print(f"Drawing dot at ({self._x}, {self._y})")
    
    def move(self, x: int, y: int) -> None:
        self._x += x
        self._y += y
        print(f"Dot moved to ({self._x}, {self._y})")

class Circle(Graphic):
    def __init__(self, x: int, y: int, radius: int):
        self._x = x
        self._y = y
        self._radius = radius
    
    def draw(self) -> None:
        print(f"Drawing circle at ({self._x}, {self._y}) with radius {self._radius}")
    
    def move(self, x: int, y: int) -> None:
        self._x += x
        self._y += y
        print(f"Circle moved to ({self._x}, {self._y})")

# Composite component
class CompoundGraphic(Graphic):
    def __init__(self):
        self._children: List[Graphic] = []
    
    def add(self, child: Graphic) -> None:
        self._children.append(child)
    
    def remove(self, child: Graphic) -> None:
        if child in self._children:
            self._children.remove(child)
    
    def draw(self) -> None:
        print("Drawing compound graphic:")
        for child in self._children:
            child.draw()
    
    def move(self, x: int, y: int) -> None:
        print(f"Moving compound graphic by ({x}, {y})")
        for child in self._children:
            child.move(x, y)

# Usage
if __name__ == "__main__":
    # Create simple graphics
    dot1 = Dot(1, 2)
    dot2 = Dot(5, 3)
    circle1 = Circle(5, 10, 3)
    circle2 = Circle(15, 25, 8)
    
    # Create compound graphics
    compound1 = CompoundGraphic()
    compound1.add(dot1)
    compound1.add(circle1)
    
    compound2 = CompoundGraphic()
    compound2.add(dot2)
    compound2.add(circle2)
    
    # Create a compound of compounds
    all_graphics = CompoundGraphic()
    all_graphics.add(compound1)
    all_graphics.add(compound2)
    
    # Draw everything
    print("Drawing all graphics:")
    all_graphics.draw()
    
    print("\nMoving all graphics:")
    all_graphics.move(10, 5)
    
    print("\nDrawing after move:")
    all_graphics.draw()
```

### 4. Decorator Pattern

#### Intent
Attach additional responsibilities to an object dynamically. Decorators provide a flexible alternative to subclassing for extending functionality.

#### Real-world Analogy
Getting dressed: You can put on different combinations of clothing layers (shirt, jacket, coat) to adapt to different weather conditions.

#### Structure
```
+-----------+       +-----------+
| Component |       | Decorator |
+-----------+       +-----------+
|operation()|       |operation()|
+-----------+       | component |
     ^              +-----------+
     |                    ^
     |                    |
+-----------+       +-----------+
|ConcreteComponent| |ConcreteDecorator|
+-----------+       +-----------+
|operation()|       |operation()|
+-----------+       |addedBehavior()|
                    +-----------+
```

#### Implementation in TypeScript
```typescript
// Component interface
interface DataSource {
    writeData(data: string): void;
    readData(): string;
}

// Concrete Component
class FileDataSource implements DataSource {
    private filename: string;
    private data: string = "";

    constructor(filename: string) {
        this.filename = filename;
    }

    writeData(data: string): void {
        console.log(`Writing data to file ${this.filename}: ${data}`);
        this.data = data;
    }

    readData(): string {
        console.log(`Reading data from file ${this.filename}`);
        return this.data;
    }
}

// Base Decorator
class DataSourceDecorator implements DataSource {
    protected wrapper: DataSource;

    constructor(source: DataSource) {
        this.wrapper = source;
    }

    writeData(data: string): void {
        this.wrapper.writeData(data);
    }

    readData(): string {
        return this.wrapper.readData();
    }
}

// Concrete Decorators
class EncryptionDecorator extends DataSourceDecorator {
    writeData(data: string): void {
        console.log("Encrypting data...");
        const encryptedData = this.encrypt(data);
        super.writeData(encryptedData);
    }

    readData(): string {
        const data = super.readData();
        console.log("Decrypting data...");
        return this.decrypt(data);
    }

    private encrypt(data: string): string {
        // Simple encryption for demo (reverse string)
        return data.split('').reverse().join('');
    }

    private decrypt(data: string): string {
        // Simple decryption for demo (reverse string)
        return data.split('').reverse().join('');
    }
}

class CompressionDecorator extends DataSourceDecorator {
    writeData(data: string): void {
        console.log("Compressing data...");
        const compressedData = this.compress(data);
        super.writeData(compressedData);
    }

    readData(): string {
        const data = super.readData();
        console.log("Decompressing data...");
        return this.decompress(data);
    }

    private compress(data: string): string {
        // Simple compression simulation
        return `COMPRESSED(${data})`;
    }

    private decompress(data: string): string {
        // Simple decompression simulation
        return data.replace('COMPRESSED(', '').replace(')', '');
    }
}

// Usage

// Apply decorators

const compressedEncryptedSource = new CompressionDecorator(encryptedSource);
```

### 5. Facade Pattern

#### Intent
Provide a unified interface to a set of interfaces in a subsystem. Facade defines a higher-level interface that makes the subsystem easier to use.

#### Real-world Analogy
Starting a car: You just turn the key (simple facade) instead of manually starting the engine, adjusting the choke, turning on lights, etc.

#### Structure
```
+--------+       +--------+
| Client |------>| Facade |
+--------+       +--------+
                 | operation()|
                 +--------+
                     |
        +------------+------------+
        |            |            |
   +--------+   +--------+   +--------+
   |SubsystemA|  |SubsystemB|  |SubsystemC|
   +--------+   +--------+   +--------+
   |operationA()|operationB()|operationC()|
   +--------+   +--------+   +--------+
```

#### Implementation in Python
```python
# Complex subsystem classes
class CPU:
    def freeze(self):
        print("CPU: Freezing processor")
    
    def jump(self, position):
        print(f"CPU: Jumping to position {position}")
    
    def execute(self):
        print("CPU: Executing instructions")

class Memory:
    def load(self, position, data):
        print(f"Memory: Loading data '{data}' at position {position}")

class SolidStateDrive:
    def read(self, lba, size):
        print(f"SSD: Reading {size} bytes from LBA {lba}")
        return f"Data from sector {lba}"

class VideoCard:
    def initialize(self):
        print("VideoCard: Initializing graphics")
    
    def load_drivers(self):
        print("VideoCard: Loading graphics drivers")

class SoundCard:
    def initialize(self):
        print("SoundCard: Initializing audio")
    
    def set_volume(self, volume):
        print(f"SoundCard: Setting volume to {volume}")

class NetworkCard:
    def initialize(self):
        print("NetworkCard: Initializing network")
    
    def connect(self):
        print("NetworkCard: Connecting to network")

# Facade
class ComputerFacade:
    def __init__(self):
        self.cpu = CPU()
        self.memory = Memory()
        self.ssd = SolidStateDrive()
        self.video_card = VideoCard()
        self.sound_card = SoundCard()
        self.network_card = NetworkCard()
    
    def start_computer(self):
        """Simple method to start the computer - hides complex subsystem interactions"""
        print("=== Starting Computer ===")
        
        # Initialize hardware
        self.video_card.initialize()
        self.video_card.load_drivers()
        self.sound_card.initialize()
        self.sound_card.set_volume(50)
        self.network_card.initialize()
        
        # Boot process
        self.cpu.freeze()
        boot_data = self.ssd.read(0, 1024)
        self.memory.load(0, boot_data)
        self.cpu.jump(0)
        self.cpu.execute()
        
        # Connect to network
        self.network_card.connect()
        
        print("=== Computer Started Successfully ===\n")
    
    def shutdown_computer(self):
        """Simple method to shutdown the computer"""
        print("=== Shutting Down Computer ===")
        print("Closing applications...")
        print("Saving user data...")
        print("Disconnecting from network...")
```

### 6. Flyweight Pattern

#### Intent
Use sharing to support large numbers of fine-grained objects efficiently.

#### Real-world Analogy
Text editor: Instead of creating a separate object for each character, the editor stores intrinsic properties (font, size) separately from extrinsic properties (position, color).

#### Structure
```
+----------+       +----------+       +----------+
|  Client  |------>| Context  |------>| Flyweight|
+----------+       +----------+       +----------+
                   |extrinsic |       |operation()|
                   |state     |       +----------+
                   +----------+              ^
                                             |
                                    +----------+
                                    |ConcreteFlyweight|
                                    +----------+
                                    |intrinsic |
                                    |state     |
                                    |operation()|
                                    +----------+
```

### 7. Proxy Pattern

#### Intent
Provide a placeholder for another object to control access to it.

#### Real-world Analogy
Credit card: A credit card is a proxy for your bank account. It provides the same interface (payment) while adding extra functionality like security and convenience.

#### Structure
```
+--------+       +--------+       +-------------+
| Client |------>| Proxy  |------>| RealSubject |
+--------+       +--------+       +-------------+
                 |request()|       | request()   |
                 +--------+       +-------------+
                      ^
                      |
              +--------+
              | Subject |
              +--------+
              |request()|
              +--------+
```

```javascript
class CachedImageProxy extends Image {
    static imageCache = new Map();

        super();
        this.filename = filename;

        if (!CachedImageProxy.imageCache.has(this.filename)) {
            console.log(`Cache miss for ${this.filename}`);
            const realImage = new RealImage(this.filename);
            CachedImageProxy.imageCache.set(this.filename, realImage);
        } else {
            console.log(`Cache hit for ${this.filename}`);
        }
        
        const cachedImage = CachedImageProxy.imageCache.get(this.filename);
        cachedImage.display();
    }

    constructor(filename, user) {
        super();
        this.filename = filename;
        this.user = user;
        this.realImage = null;

    hasAccess() {
        // Simple access control - only admin can access restricted images
        return this.user === 'admin' || !this.filename.includes('restricted');
    }
    
    display() {
        if (!this.hasAccess()) {
            console.log(`Access denied for ${this.user} to view ${this.filename}`);
            return;
        }
        
        if (this.realImage === null) {
            this.realImage = new RealImage(this.filename);

    }
```

```python
from abc import ABC, abstractmethod
import time

# Subject interface
class BankAccount(ABC):
    @abstractmethod
    def deposit(self, amount: float) -> None:
        pass
    
    @abstractmethod
    def withdraw(self, amount: float) -> bool:
        pass
    
    @abstractmethod
    def get_balance(self) -> float:
        pass

# Real Subject
class RealBankAccount(BankAccount):
    def __init__(self, account_number: str, initial_balance: float = 0):
        self._account_number = account_number
        self._balance = initial_balance
        print(f"Real bank account {account_number} created with balance ${initial_balance}")
    
    def deposit(self, amount: float) -> None:
        if amount > 0:
            self._balance += amount
            print(f"Deposited ${amount}. New balance: ${self._balance}")
        else:
            print("Invalid deposit amount")
    
    def withdraw(self, amount: float) -> bool:
        if amount > 0 and amount <= self._balance:
            self._balance -= amount
            print(f"Withdrew ${amount}. New balance: ${self._balance}")
            return True
        else:
            print("Invalid withdrawal amount or insufficient funds")
            return False
    
    def get_balance(self) -> float:
        return self._balance

# Proxy with access control and logging
class BankAccountProxy(BankAccount):
    def __init__(self, account_number: str, pin: str, initial_balance: float = 0):
        self._account_number = account_number
        self._correct_pin = pin
        self._initial_balance = initial_balance
        self._real_account = None
        self._is_authenticated = False
        self._login_attempts = 0
        self._max_attempts = 3
        self._locked = False
    
    def authenticate(self, pin: str) -> bool:
        if self._locked:
            print("Account is locked due to too many failed attempts")
            return False
        
        if pin == self._correct_pin:
            self._is_authenticated = True
            self._login_attempts = 0
            print("Authentication successful")
            
            # Lazy initialization - create real account only after authentication
            if self._real_account is None:
                self._real_account = RealBankAccount(self._account_number, self._initial_balance)
            
            return True
        else:
            self._login_attempts += 1
            print(f"Authentication failed. Attempts: {self._login_attempts}/{self._max_attempts}")
            
            if self._login_attempts >= self._max_attempts:
                self._locked = True
                print("Account locked due to too many failed attempts")
            
            return False
    
    def _check_authentication(self) -> bool:
        if not self._is_authenticated:
            print("Access denied. Please authenticate first.")
            return False
        return True
    
    def _log_transaction(self, operation: str, amount: float = None):
        timestamp = time.strftime("%Y-%m-%d %H:%M:%S")
        if amount is not None:
            print(f"[LOG {timestamp}] {operation}: ${amount} on account {self._account_number}")
        else:
            print(f"[LOG {timestamp}] {operation} on account {self._account_number}")
    
    def deposit(self, amount: float) -> None:
        if not self._check_authentication():
            return
        
        self._log_transaction("DEPOSIT", amount)
        self._real_account.deposit(amount)
    
    def withdraw(self, amount: float) -> bool:
        if not self._check_authentication():
            return False
        
        self._log_transaction("WITHDRAWAL", amount)
        return self._real_account.withdraw(amount)
    
    def get_balance(self) -> float:
        if not self._check_authentication():
            return 0.0
        
        self._log_transaction("BALANCE_INQUIRY")
        return self._real_account.get_balance()
```

#### Types of Proxy Patterns

1. **Virtual Proxy**: Controls creation of expensive objects (lazy initialization)
2. **Protection Proxy**: Controls access to sensitive objects based on permissions
3. **Remote Proxy**: Manages communication with objects in different address spaces
4. **Smart Reference**: Provides additional functionality when accessing objects
5. **Cache Proxy**: Provides caching mechanism for expensive operations
6. **Synchronization Proxy**: Controls access to objects in multi-threaded environments

#### Use Cases
- **Lazy Loading**: Creating expensive objects only when needed
- **Access Control**: Implementing authentication and authorization
- **Caching**: Storing results of expensive operations
- **Remote Objects**: Providing local representation of remote objects
- **Logging**: Adding logging capabilities without modifying original objects

## 🧠 Comparing Structural Patterns

### Pattern Selection Guide

| Pattern | When to Use |
|---------|------------|
| **Adapter** | When you need to use an existing class with an incompatible interface |
| **Bridge** | When you want to avoid permanent binding between abstraction and implementation |
| **Composite** | When you want to represent part-whole hierarchies as tree structures |
| **Decorator** | When you want to add responsibilities to objects dynamically |
| **Facade** | When you want to provide a simple interface to a complex subsystem |
| **Flyweight** | When you need to support large numbers of fine-grained objects efficiently |
| **Proxy** | When you need a placeholder to control access to another object |

### Key Differences

- **Adapter vs Bridge**: Adapter works with existing interfaces; Bridge designs the abstraction and implementation to vary independently
- **Composite vs Decorator**: Composite focuses on structure; Decorator focuses on adding responsibilities
- **Facade vs Adapter**: Facade simplifies interface; Adapter makes incompatible interfaces work together
- **Proxy vs Decorator**: Proxy controls access; Decorator adds functionality
- **Flyweight vs Singleton**: Flyweight manages multiple similar objects; Singleton ensures single instance

## 📚 Best Practices for Structural Patterns

### General Guidelines

1. **Choose the Right Pattern**: Understand the problem before selecting a pattern
2. **Keep It Simple**: Don't over-engineer solutions
3. **Consider Performance**: Some patterns add overhead
4. **Think About Maintenance**: Consider how easy it will be to modify the code later
5. **Document Decisions**: Explain why a particular pattern was chosen

### Pattern-Specific Tips

#### Adapter
- Prefer object adapter over class adapter for flexibility
- Consider using adapter for legacy system integration
- Keep adapters focused on interface translation only

#### Bridge
- Use when both abstractions and implementations need to be extended
- Consider when you have a proliferation of classes from a two-dimensional inheritance hierarchy

#### Composite
- Ensure leaf and composite objects implement the same interface
- Be careful with operations that don't make sense for all components
- Consider using visitor pattern for operations that vary by component type

#### Decorator
- Keep the component interface stable
- Consider using decorator when subclassing would result in an explosion of classes
- Be careful about object identity when using decorators

#### Facade
- Don't make the facade too complex
- Allow clients to access subsystems directly if needed
- Consider multiple facades for different client needs

#### Flyweight
- Only use when you have a large number of objects with shared intrinsic state
- Carefully separate intrinsic and extrinsic state
- Consider the complexity added by the pattern

#### Proxy
- Choose the right type of proxy for your needs
- Consider the overhead added by proxy indirection
- Ensure proxy implements the same interface as the subject

## 🔄 Anti-patterns in Structural Design

### Common Mistakes

1. **Overuse of Adapter**: Creating adapters when interfaces should be redesigned
2. **Complex Facade**: Making facades too complex and defeating their purpose
3. **Inappropriate Composite**: Using composite for simple containment relationships
4. **Decorator Explosion**: Creating too many small decorator classes
5. **Proxy Overhead**: Adding proxy layers that don't provide value
6. **Flyweight Misuse**: Using flyweight when objects don't have significant shared state

### How to Avoid

1. **Analyze the Problem**: Understand the actual problem before applying patterns
2. **Consider Alternatives**: Sometimes simpler solutions are better
3. **Measure Performance**: Verify that patterns improve rather than hurt performance
4. **Refactor Gradually**: Introduce patterns incrementally
5. **Get Feedback**: Have peers review pattern usage

## 📝 Conclusion

Structural design patterns are powerful tools for organizing code and managing relationships between objects. They help create flexible, maintainable systems by focusing on how objects are composed and how they collaborate.

The key to using structural patterns effectively is understanding when each pattern applies and recognizing the trade-offs involved. Remember that patterns should solve actual problems, not be used for their own sake.

As you gain experience with these patterns, you'll develop intuition for when to apply them and how to combine them effectively. The goal is always to create code that is easier to understand, maintain, and extend.
