3. Application Strategy​

The 50-application rule​

The first 50 applications are practice. You won't get responses. You're testing:

  • Does your headline attract attention?
  • Does your proposal template get reads?
  • Which roles have the best fit?

Track everything from application 1. By application 25, you should see patterns. By application 50, you should have at least 3 active conversations.

Additional interview questions (beyond the 10 in Phase 5)​

Q11: How do you handle streaming responses in a RAG system?

from fastapi.responses import StreamingResponse
from langgraph.graph import StateGraph

async def stream_rag(query: str):
    async for token in rag_pipeline.astream(query):
        yield f"data: {token}\n\n"

@app.get("/v1/stream")
async def stream_endpoint(query: str):
    return StreamingResponse(
        stream_rag(query),
        media_type="text/event-stream",
    )

Q12: How do you log and trace agent runs? Each LLM call gets a unique trace ID. Every log line includes: trace_id, phase (retrieve, generate, tool_call), model, token count, latency. Send to a structured logging service (or just JSON files rotated daily).

Q13: How do you handle LLM API failures?

  1. Retry with exponential backoff (max 3 retries)
  2. Fallback model (if GPT-4 fails, try Claude)
  3. Cache identical requests (same input ? same output within TTL)
  4. Degrade gracefully (return cached results, tell user the system is warming up)

Q14: Explain the tradeoffs of local vs cloud LLMs.

FactorLocal LLM (Ollama, vLLM)Cloud LLM (OpenAI, Anthropic)
LatencyHigher (no network call but slower inference)Network latency + model latency
CostFixed (GPU rental)Variable (per token)
PrivacyData stays on your hardwareData leaves your network
QualityLower for complex reasoningState of the art
MaintenanceYou manage GPUs, updatesZero maintenance
Best forPrivacy-sensitive, high volumeComplex reasoning, production

Q15: How would you design a multi-tenant RAG system? Each tenant gets an isolated collection in ChromaDB. API keys map to tenant IDs via middleware. Document ingestion is tenant-scoped. Query retrieval only searches the requesting tenant's collection. Rate limiting is per-tenant (token bucket). Cost tracking is per-tenant for billing.

Q16: How do you handle context window limits in long conversations? Three strategies:

  1. Sliding window — keep the last N messages, drop older ones
  2. Summarization — periodically summarize old context into a system message
  3. Selective retrieval — retrieve only the 5 most relevant past exchanges using vector similarity on conversation history

Behavioral questions (STAR method)​

Have 5 stories ready using Situation ? Task ? Action ? Result.

Story 1: Technical challenge

  • S: n8n workflow kept crashing mid-run with no recovery
  • T: Needed a reliable stateful pipeline
  • A: Ported to LangGraph with checkpoint persistence
  • R: Zero data loss, can resume from any failed node

Story 2: Conflict resolution

  • S: Client wanted a chatbot, needed a RAG system
  • T: Educate on why RAG wins over fine-tuning
  • A: Built a prototype showing RAG with citations vs fine-tuned hallucination
  • R: Client chose RAG, saved 3 months of training time

Story 3: Leadership/ownership

  • S: Multi-tenant ERP had no caching strategy
  • T: Reduce DB load without breaking existing queries
  • A: Added Redis caching layer with per-tenant TTLs
  • R: 60% reduction in DB queries, zero downtime

Story 4: Failure

  • S: Deployed a buggy migration that dropped a column
  • T: Fix without data loss
  • A: Rolled back, restored from backup, fixed migration script
  • R: 15 minutes of downtime, no data loss, added rollback tests to CI
  • Lesson: Always test downgrade before deploying upgrades

Story 5: Learning/growth

  • S: Had never built an AI system before this course
  • T: Go from zero to deployed RAG + agent pipeline
  • A: Followed a structured curriculum, built 2 projects
  • R: Deployed production RAG API + LangGraph workflow in 12 weeks

Take-home project strategy​

If you get a take-home assignment, here's how to ace it:

  1. Read the spec twice before writing any code
  2. Spend 30 min on architecture before coding
  3. Add tests — this is the easiest way to stand out
  4. Write a README explaining your decisions
  5. Include a demo (if it's an API, deploy it temporarily)
  6. Document tradeoffs — shows senior thinking
  7. Ship early — 80% perfect on day 3 beats 100% perfect on day 7

Handling rejection​

  1. Rejection is data, not judgment. If you get rejected after an interview, ask for feedback: "What was the deciding factor?"
  2. If response rate is low ( < 20%), your profile or proposal needs work
  3. If interview-to-offer rate is low, you need more interview practice
  4. If you're not getting interviews, your portfolio isn't convincing enough

interface LogEntry { timestamp: string; level: "info"|"warn"|"error"|"debug"; message: string; metadata?: Record&lt;string,unknown&gt; }
interface Span { id: string; parentId?: string; name: string; startTime: number; endTime?: number; tags: Record&lt;string,string&gt; }

class Logger {
  private entries: LogEntry[] = []
  private log(level: LogEntry["level"], message: string, metadata?: Record&lt;string,unknown&gt;): void {
    const entry: LogEntry = {timestamp:new Date().toISOString(),level,message,metadata}
    this.entries.push(entry); console[JSON.stringify(entry)]
  }
  info(m:string,m2?:Record&lt;string,unknown&gt;): void { this.log("info",m,m2) }
  warn(m:string,m2?:Record&lt;string,unknown&gt;): void { this.log("warn",m,m2) }
  error(m:string,m2?:Record&lt;string,unknown&gt;): void { this.log("error",m,m2) }
  debug(m:string,m2?:Record&lt;string,unknown&gt;): void { this.log("debug",m,m2) }
  getRecent(n:number): LogEntry[] { return this.entries.slice(-n) }
}
class Tracer {
  private spans: Map&lt;string,Span&gt; = new Map()
  start(name: string, parentId?: string): Span {
    const id = crypto.randomUUID(); const span: Span = {id,parentId,name,startTime:Date.now(),tags:{}}
    this.spans.set(id,span); return span
  }
  end(span: Span): void { span.endTime = Date.now() }
  getTrace(spanId: string): Span[] {
    const result: Span[] = []; const stack: string[] = [spanId]
    while(stack.length) { const id = stack.pop()!; const span = this.spans.get(id); if(span){result.push(span);this.spans.forEach((s,k)=>{if(s.parentId===id)stack.push(k)})} }
    return result
  }
}
class MetricsCollector {
  private metrics: Metric[] = []
  record(name: string, value: number, tags?: Record&lt;string,string&gt;): void { this.metrics.push({name,value,tags:tags??{},timestamp:Date.now()}) }
  avg(name: string, windowMs: number): number {
    const cutoff = Date.now()-windowMs; const filtered = this.metrics.filter(m=>m.name===name&&m.timestamp>=cutoff)
    return filtered.length?filtered.reduce((s,m)=>s+m.value,0)/filtered.length:0
  }
}
