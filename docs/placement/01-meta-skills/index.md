### Memory Systems

**Working Memory:**
- Capacity: Sirf 4±1 items ek saath (Miller's Law)
- Duration: 15-30 seconds bina rehearsal ke
- Improvement: Chunking karo, cognitive load kam karo

**Long-Term Memory:**
- **Declarative:** Facts, concepts (semantic) + personal experiences (episodic)
- **Procedural:** Skills, habits — repetition se strong hoti hai

**Memory Formation — 3 Stages:**
1. **Encoding** — Information input (padhna, dekhna, sunna)
2. **Consolidation** — Working memory → Long-term storage
3. **Retrieval** — Accessing information (test yourself, recall karo)

**Key Insight:** Retrieval practice (bina dekhe yaad karna) re-read se zyada powerful hai. Roediger & Karpicke (2006) ke research mein 50% better retention mila 1 week baad. Isliye flashcards aur practice problems use karo.

### Chunking Strategies

<div class="phase-section">
  <div class="phase-header">🧩 Complex Topics → Small Bite-Sized Chunks</div>
  <div class="phase-body">
    <p><strong>What is chunking?</strong> Working memory sirf 4±1 items hold kar sakta hai. Chunking = complex information ko meaningful groups mein todna jo brain easily process kare.</p>
    <p><strong>Example — Merge Sort broken down:</strong></p>
    <ul>
      <li><strong>Divide:</strong> Array recursively split until single elements remain</li>
      <li><strong>Conquer:</strong> Each pair sorted recursively</li>
      <li><strong>Combine:</strong> Merge two sorted arrays into one sorted array</li>
    </ul>
    <p><strong>Chunking framework for any topic:</strong> 1) Identify 3-5 main components  2) Master each component individually  3) Practice combining them together  4) Once automatic, celebrate — chunk formed!</p>
  </div>
</div>

### Debugging Workflow

<div class="phase-section">
  <div class="phase-header">🐛 Systematic Debugging Framework</div>
  <div class="phase-body">
    <p><strong>Step 1 — Isolate:</strong> Exact bug location identify karo. Print/console.log statements use karo. Binary search approach: half code check karo, bug uss half mein hai ya dusre mein.</p>
    <p><strong>Step 2 — Hypothesize:</strong> "Maybe this edge case isn't handled" ya "Off-by-one error in loop." Hypothesis clear statement honi chahiye — random guessing nahi.</p>
    <p><strong>Step 3 — Test:</strong> Hypothesis prove/disprove karo. Small input leke manually trace karo. Expected output vs actual output compare.</p>
    <p><strong>Step 4 — Confirm:</strong> Fix apply karo → all test cases run → edge cases check → regression ensure karo that old tests still pass.</p>
    <p><strong>Golden Rule:</strong> Har fix ke peeche reason hona chahiye. "Let me just try this" approach bhool jao — systematic debugging faster hai.</p>
  </div>

### Problem-Solving Template for DSA

<div class="phase-section">
  <div class="phase-header">🧩 5-Step DSA Problem Framework</div>
  <div class="phase-body">
    <p><strong>1. Understand (3-5 min):</strong> Input kya hai? Output kya hai? Constraints batati hain ki O(n²) chalega ya nahi. Edge cases puchho: Empty input? Single element? Negative numbers? Already sorted?</p>
    <p><strong>2. Brute Force (3-5 min):</strong> Simplest solution jo dimaag mein aaye. Time/space complexity batado. Accept karo ki ye optimal nahi hai — interview mein yahi approach expected hai.</p>
    <p><strong>3. Optimize (10-15 min):</strong> Brute force mein inefficiency kahan hai? Better data structure? Algorithm pattern recognize karo (Sliding window? Two pointers? DP? Graph?). Time/space trade-offs discuss karo with interviewer.</p>
    <p><strong>4. Test / Dry Run (2-3 min):</strong> Small example leke manually trace karo. Edge cases check karo. "Let me trace through an example to verify" — interviewer impressed.</p>
    <p><strong>5. Implement (10-15 min):</strong> Clean code with descriptive variable names. Helper functions for modularity. Handle all discussed edge cases. Comment only where intent isn't obvious.</p>
  </div>
</div>

<div class="tip-banner">
  <span class="tip-badge">⚡ DSA INTERVIEW SEQUENCE</span>
  Problem dekhne ke baad: <strong>1. Clarify → 2. Brute force → 3. Discuss optimization → 4. Dry run → 5. Write clean code</strong>. Is sequence ko 50+ problems mein practice karo — automatic ho jayega interview mein.
</div>

### Deep Work (Cal Newport)

<div class="phase-section">
  <div class="phase-header">⚡ Deep Work — The Superpower for Placement</div>
  <div class="phase-body">
    <p><strong>Definition:</strong> Deep work = distraction-free, focused, high-cognitive-demand work. Placement prep mein deep work = DSA problem-solving, system design thinking, new algorithm learning.</p>
    <p><strong>Daily target:</strong> 2-4 hours of deep work minimum. First 4 hours highest returns — after that diminishing returns. Quality > quantity.</p>

### James Clear's 4 Laws of Habit Formation

<div class="phase-section">
  <div class="phase-header">📖 The 4 Laws Applied to Placement Prep</div>
  <div class="phase-body">
    <p><strong>Law 1 — Make It Obvious:</strong> Keep DSA book on the desk (visible cue). Phone in another room (invisible). Browser shortcuts to LeetCode/Anki on home screen. Environment design > willpower.</p>
    <p><strong>Law 2 — Make It Attractive:</strong> Study with a friend (social accountability). Pair programming for DSA. Temptation bundling: "I will listen to my favorite podcast ONLY while doing flashcards."</p>
    <p><strong>Law 3 — Make It Easy:</strong> Start with 2 minutes. "I will open LeetCode and read one problem" — leads to solving 2-3. Reduce friction: laptop already open, desk already clean.</p>
    <p><strong>Law 4 — Make It Satisfying:</strong> Track with checkmarks (visual reward). Share daily progress (accountability + satisfaction). Reward after study session (walk, snack, episode). Immediate rewards program long-term habits.</p>
  </div>
</div>

### Topic Mastery Checklist

<div class="phase-section">
  <div class="phase-header">✅ From First Exposure to Mastery</div>
  <div class="phase-body">
    <p><strong>[ ] Watch / Read:</strong> Concept introduction — video ya article. 1.5x speed if familiar. Just understand the core idea — don't try to memorize yet.</p>
    <p><strong>[ ] Read + Annotate:</strong> Active reading — questions banao, examples trace karo, code execution manually follow karo.</p>
    <p><strong>[ ] Implement Code:</strong> Khud likho from scratch — copy nahi. Implementation details yahan clear hote hain. Debug any errors.</p>
    <p><strong>[ ] Solve 5+ Problems:</strong> Start easy → medium → hard. Minimum 1-2 per difficulty level. Pattern recognition yahan hoti hai.</p>
    <p><strong>[ ] Teach Someone:</strong> Feynman technique — kisi ko samjhao ya rubber duck ko. Gaps immediately clear ho jate hain.</p>
    <p><strong>[ ] Review After 1 Week:</strong> Solve 2-3 problems without reference. If you can solve independently — topic mastered. If not, re-activate.</p>
