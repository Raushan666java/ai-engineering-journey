### 14.1 I/O Subsystem Overview

The I/O subsystem connects the processor and memory to external devices such as keyboards, displays, storage devices, and network interfaces. The subsystem must manage the significant speed disparity between processors (nanoseconds) and mechanical devices (milliseconds).

### 14.2 I/O Methods

Three fundamental approaches to managing I/O operations exist.

#### 14.2.1 Programmed I/O

The processor executes a polling loop, repeatedly checking the device status register until the device is ready for data transfer. The processor is fully occupied during the transfer.

**Advantages**: Simple to implement, predictable timing.
**Disadvantages**: Wastes CPU cycles that could be used for computation.

```
Polling loop:
loop: READ status_register
      TEST ready_bit
      BRANCH if not ready to loop
      READ data_register
```

#### 14.2.2 Interrupt-Driven I/O

The device signals the processor via an interrupt request (IRQ) when it is ready to transfer data. The processor saves its current state, executes an interrupt service routine (ISR) to perform the transfer, and returns to the interrupted program.

**Interrupt sequence**:

1. Device asserts interrupt request.
2. Processor completes the current instruction.
3. Processor saves the PC and status register.
4. Processor determines the interrupt source (vectored or polled).
5. Processor loads the ISR address into the PC.
6. ISR saves registers, services the device, restores registers.
7. Processor executes return-from-interrupt (RTI or IRET), restoring the saved PC.

**Advantages**: Processor only intervenes when I/O is needed; computing and I/O overlap.
**Disadvantages**: Overhead of context switching; interrupt storms can degrade performance.

#### 14.2.3 Direct Memory Access (DMA)

A DMA controller transfers data directly between the I/O device and memory without processor involvement. The processor initialises the DMA transfer (source address, destination address, count) and the DMA controller manages the data movement.

**DMA transfer sequence**:

1. Processor programmes the DMA controller: source, destination, byte count, direction.
2. DMA controller requests bus control from the processor.
3. DMA controller transfers data in burst or cycle-stealing mode.
4. DMA controller asserts an interrupt when the transfer is complete.

**Burst mode**: The DMA controller holds the bus for the entire transfer.
**Cycle-stealing mode**: The DMA controller transfers one word at a time, releasing the bus between transfers.

### 14.3 Interrupts

#### 14.3.1 Interrupt Types

- **Maskable interrupts**: Can be disabled by the processor (enabled/disabled via the interrupt flag).
- **Non-maskable interrupts (NMI)**: Cannot be disabled; used for critical events such as power failure.
- **Software interrupts (traps)**: Generated by executing an explicit instruction (e.g., SYSCALL).

#### 14.3.2 Interrupt Priority

Multiple devices may generate interrupts simultaneously. A priority scheme determines the order in which interrupts are serviced.

**Fixed priority**: A priority encoder assigns the highest priority to the device with the highest index.

**Daisy chain**: Interrupt acknowledge signals propagate through devices in a chain. A device closer to the processor has higher priority.

**Programmable priority**: The priority levels are stored in registers and can be reconfigured.

#### 14.3.3 Vectored Interrupts

Each interrupting device provides a vector (a number) that the processor uses to index into an interrupt vector table, obtaining the address of the ISR. Vectored interrupts reduce the latency of interrupt handling compared to polled interrupts.

### 14.4 I/O Buses

An I/O bus is a shared communication channel connecting the processor, memory, and I/O devices.

#### 14.4.1 Bus Signals

- **Data lines**: Carry data between components.
- **Address lines**: Specify the source or destination of data.
- **Control lines**: Signal timing, direction, and bus requests.

#### 14.4.2 Bus Arbitration

Multiple devices may request bus access simultaneously. The bus arbiter grants access according to a policy:

- **Centralised arbitration**: A single arbiter receives requests and grants access.
- **Distributed arbitration**: Devices collectively determine access using a priority scheme.

#### 14.4.3 Common Bus Standards

### 14.5 I/O Processors

An I/O processor (IOP) is a specialised processor that executes I/O programs independently of the main CPU. The IOP fetches I/O instructions from memory, interprets them, and performs the required I/O operations. The main CPU sends high-level commands to the IOP and receives status information upon completion.

**Advantages**:
- Full overlap of I/O and computation
- Offloads I/O processing from the main CPU
- Handles error recovery and retry logic

### 14.6 Memory-Mapped I/O

In memory-mapped I/O, device registers are assigned addresses in the processor's memory address space. Load and store instructions are used to communicate with devices, eliminating the need for special I/O instructions.

**Advantages**: No special I/O instructions needed; all memory access instructions can be used.
**Disadvantages**: Consumes address space that could be used for memory; caches may interfere with device register access (caching must be disabled for device registers).

## Examples

### Example 14.1: Programmed I/O Overhead

A keyboard generates 100 characters per second. Each poll takes 200 ns. The processor runs at 2 GHz. Calculate the fraction of CPU time consumed by polling.

**Solution**: The processor must poll frequently enough not to miss a character. If it polls every 5 ms (half the time between characters), polling frequency = 200 Hz. Time per second = 200 &times; 200 ns = 40 &mu;s. Fraction = 40 &mu;s / 1 s = 0.004% — negligible overhead.

### Example 14.2: DMA Transfer

A DMA controller transfers 8 KB of data from a disk to memory. The bus transfer rate is 200 MB/s. Calculate the transfer time in burst mode. How much time does the DMA steal from the processor in cycle-stealing mode if the processor runs at 2 GHz?

**Solution**: Transfer time = 8 KB / 200 MB/s = 8192 / 200,000,000 = 40.96 &mu;s. In cycle-stealing mode: each 32-bit word (4 bytes) requires one bus cycle. Each bus cycle steals 1 processor cycle = 0.5 ns. Total steals = (8192 / 4) &times; 0.5 ns = 2048 &times; 0.5 ns = 1.024 &mu;s.

### Example 14.3: Interrupt Latency

An interrupt handler takes 50 cycles to save and restore registers. The ISR for a disk transfer takes 200 cycles to service. At 2 GHz, what fraction of the CPU is consumed by interrupts if the disk generates 1000 interrupts per second?

**Solution**: Total cycles per interrupt = 50 + 200 = 250 cycles. Total time per interrupt = 250 / 2 &times; 10^9 = 125 ns. Total time per second = 1000 &times; 125 ns = 125 &mu;s. Fraction = 0.0125%.

## Summary

- Programmed I/O (polling) is simple but wastes CPU cycles.
- Interrupt-driven I/O enables overlap of computing and I/O but incurs context-switch overhead.
- DMA transfers data independently, freeing the CPU for computation.
- Bus arbitration resolves simultaneous access requests from multiple devices.
- Memory-mapped I/O treats device registers as memory locations for convenient access.
