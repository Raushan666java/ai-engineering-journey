# Functional vs Non-Functional Requirements - Complete Analysis Guide
## Understanding the Foundation of Software Systems

## 📋 Overview
Requirements form the foundation of any software system. Understanding the distinction between functional and non-functional requirements is crucial for building systems that not only work correctly but also perform well, remain secure, and provide excellent user experience.

## 🔧 Functional Requirements Deep Dive

### Definition and Characteristics
**Functional Requirements** define what the system should do - the specific behaviors, functions, and features that the system must provide to meet user needs and business objectives.

**Key Characteristics:**
- Describe system behavior and functionality
- Define inputs, processing, and outputs
- Specify user interactions and workflows
- Detail business rules and logic
- Can be tested through functional testing

```markdown
**Title:** User Authentication

**Description:** 
The system shall provide secure user authentication functionality allowing registered users to access their accounts.

**Preconditions:**
- User has a valid account in the system
- User is on the login page

**Input:**
- Username/Email (String, required)

2. Check credentials against database
3. Generate session token if valid
4. Log authentication attempt

**Output:**

- Failure: Display error message and remain on login page

- User session is established (success case)
- Authentication attempt is logged

- Maximum 3 failed attempts before account lockout
- Session expires after 30 minutes of inactivity
- Password must meet complexity requirements

**Acceptance Criteria:**
- Given valid credentials, user is logged in successfully
- Given invalid credentials, appropriate error message is displayed
- Given locked account, user cannot login until unlocked

**Priority:** High
**Complexity:** Medium
**Dependencies:** User Registration (FR002)
```

## 🎯 Non-Functional Requirements Deep Dive

### Definition and Characteristics
**Non-Functional Requirements (NFRs)** define how the system should perform - the quality attributes, constraints, and standards that the system must meet.

**Key Characteristics:**
- Define system quality attributes
- Specify performance criteria
- Set constraints and standards
- Often measurable and quantifiable
- Tested through non-functional testing

## 🔄 Requirements Traceability Matrix

### Functional to Non-Functional Mapping
```python
class RequirementsTraceability:
    def __init__(self):
        self.requirements_map = {}
        self.test_cases = {}
    
    def add_functional_requirement(self, fr_id, description, related_nfrs=None):
        self.requirements_map[fr_id] = {
            'type': 'functional',
            'description': description,
            'related_nfrs': related_nfrs or [],
            'test_cases': [],
            'status': 'draft'
        }
    
    def add_non_functional_requirement(self, nfr_id, category, description, metrics):
        self.requirements_map[nfr_id] = {
            'type': 'non-functional',
            'category': category,
            'description': description,
            'metrics': metrics,
            'test_cases': [],
            'status': 'draft'
        }
    
    def link_requirements(self, fr_id, nfr_id):
        if fr_id in self.requirements_map and nfr_id in self.requirements_map:
            self.requirements_map[fr_id]['related_nfrs'].append(nfr_id)
    
    def add_test_case(self, req_id, test_case_id, description):
        if req_id in self.requirements_map:
            self.requirements_map[req_id]['test_cases'].append({
                'id': test_case_id,
                'description': description,
                'status': 'not_executed'
            })
    
    def generate_traceability_report(self):
        report = []
        for req_id, req_data in self.requirements_map.items():
            report.append({
                'requirement_id': req_id,
                'type': req_data['type'],
                'description': req_data['description'],
                'test_coverage': len(req_data['test_cases']),
                'related_requirements': req_data.get('related_nfrs', [])
            })
        return report

# Usage Example
traceability = RequirementsTraceability()

# Add functional requirement
traceability.add_functional_requirement(
    'FR001', 
    'User login functionality',
    ['NFR001', 'NFR015']
)

# Add non-functional requirements
traceability.add_non_functional_requirement(
    'NFR001',
    'Performance',
    'Login response time',
    {'target': '< 2 seconds', 'measurement': 'response time'}
)

traceability.add_non_functional_requirement(
    'NFR015',
    'Security',
    'Password encryption',
    {'standard': 'bcrypt', 'strength': 'minimum 12 rounds'}
)

# Add test cases
traceability.add_test_case('FR001', 'TC001', 'Test valid login')
traceability.add_test_case('NFR001', 'TC002', 'Test login response time')
```

### MoSCoW Prioritization
```python
class MoSCoWPrioritization:
    def __init__(self):
        self.requirements = {
            'must_have': [],
            'should_have': [],
            'could_have': [],
            'wont_have': []
        }
    
    def add_requirement(self, req_id, description, priority, business_value, effort):
        requirement = {
            'id': req_id,
            'description': description,
            'business_value': business_value,
            'effort': effort,
            'value_effort_ratio': business_value / effort if effort > 0 else 0
        }
        
        if priority.lower() in self.requirements:
            self.requirements[priority.lower()].append(requirement)
    
    def get_prioritized_list(self):
        prioritized = []
        for category in ['must_have', 'should_have', 'could_have', 'wont_have']:
            # Sort by value/effort ratio within each category
            sorted_reqs = sorted(
                self.requirements[category], 
                key=lambda x: x['value_effort_ratio'], 
                reverse=True
            )
            prioritized.extend(sorted_reqs)
        return prioritized

# Usage Example
moscow = MoSCoWPrioritization()
moscow.add_requirement('FR001', 'User authentication', 'must_have', 10, 5)
moscow.add_requirement('FR002', 'Password reset', 'should_have', 7, 3)
moscow.add_requirement('FR003', 'Social media login', 'could_have', 5, 8)
moscow.add_requirement('FR004', 'Biometric login', 'wont_have', 8, 15)
```

### Kano Model Analysis
```python
class KanoModel:
    def __init__(self):
        self.requirements = []
    
    def add_requirement(self, req_id, description, kano_category):
        """
        Kano Categories:
        - basic: Must-be quality (expected features)
        - performance: One-dimensional quality (more is better)
        - excitement: Attractive quality (delighters)
        - indifferent: Features that don't affect satisfaction
        - reverse: Features that decrease satisfaction
        """
        self.requirements.append({
            'id': req_id,
            'description': description,
            'category': kano_category,
            'satisfaction_impact': self._get_satisfaction_impact(kano_category)
        })
    
    def _get_satisfaction_impact(self, category):
        impact_map = {
            'basic': {'present': 0, 'absent': -10},
            'performance': {'present': 5, 'absent': -5},
            'excitement': {'present': 10, 'absent': 0},
            'indifferent': {'present': 0, 'absent': 0},
            'reverse': {'present': -5, 'absent': 0}
        }
        return impact_map.get(category, {'present': 0, 'absent': 0})
    
    def prioritize_by_satisfaction(self):
        return sorted(
            self.requirements,
            key=lambda x: x['satisfaction_impact']['present'],
            reverse=True
        )

# Usage Example
kano = KanoModel()
kano.add_requirement('FR001', 'User login', 'basic')
kano.add_requirement('FR002', 'Fast search', 'performance')
kano.add_requirement('FR003', 'AI recommendations', 'excitement')
```

## 🧪 Requirements Testing and Validation

### Functional Requirements Testing
```python
class FunctionalRequirementTester:
    def __init__(self):
        self.test_results = {}
    
    def test_requirement(self, req_id, test_cases):
        """Test functional requirement with multiple test cases"""
        results = []
        for test_case in test_cases:
            result = self._execute_test_case(test_case)
            results.append(result)
        
        self.test_results[req_id] = {
            'total_tests': len(test_cases),
            'passed': sum(1 for r in results if r['status'] == 'pass'),
            'failed': sum(1 for r in results if r['status'] == 'fail'),
            'results': results
        }
        
        return self.test_results[req_id]
    
    def _execute_test_case(self, test_case):
        """Execute individual test case"""
        try:
            # Simulate test execution
            expected = test_case['expected']
            actual = test_case['actual']
            
            if expected == actual:
                return {
                    'test_id': test_case['id'],
                    'status': 'pass',
                    'message': 'Test passed successfully'
                }
            else:
                return {
                    'test_id': test_case['id'],
                    'status': 'fail',
                    'message': f'Expected {expected}, got {actual}'
                }
        except Exception as e:
            return {
                'test_id': test_case['id'],
                'status': 'error',
                'message': str(e)
            }

# Usage Example
tester = FunctionalRequirementTester()
test_cases = [
    {'id': 'TC001', 'expected': 'success', 'actual': 'success'},
    {'id': 'TC002', 'expected': 'error', 'actual': 'error'},
    {'id': 'TC003', 'expected': 'redirect', 'actual': 'redirect'}
]
result = tester.test_requirement('FR001', test_cases)
```

### Non-Functional Requirements Testing
```python
class NonFunctionalRequirementTester:
    def __init__(self):
        self.performance_results = {}
        self.security_results = {}
    
    def test_performance_requirement(self, nfr_id, target_metric, actual_metric):
        """Test performance requirements"""
        result = {
            'requirement_id': nfr_id,
            'target': target_metric,
            'actual': actual_metric,
            'status': 'pass' if actual_metric <= target_metric else 'fail',
            'variance': ((actual_metric - target_metric) / target_metric) * 100
        }
        
        self.performance_results[nfr_id] = result
        return result
    
    def test_security_requirement(self, nfr_id, security_checks):
        """Test security requirements"""
        passed_checks = sum(1 for check in security_checks if check['result'])
        total_checks = len(security_checks)
        
        result = {
            'requirement_id': nfr_id,
            'total_checks': total_checks,
            'passed_checks': passed_checks,
            'pass_rate': (passed_checks / total_checks) * 100,
            'status': 'pass' if passed_checks == total_checks else 'fail',
            'failed_checks': [check['name'] for check in security_checks if not check['result']]
        }
        
        self.security_results[nfr_id] = result
        return result
    
    def generate_nfr_report(self):
        """Generate comprehensive NFR test report"""
        return {
            'performance_tests': self.performance_results,
            'security_tests': self.security_results,
            'overall_status': self._calculate_overall_status()
        }
    
    def _calculate_overall_status(self):
        all_results = list(self.performance_results.values()) + list(self.security_results.values())
        if not all_results:
            return 'no_tests'
        
        failed_tests = sum(1 for result in all_results if result['status'] == 'fail')
        return 'pass' if failed_tests == 0 else 'fail'

# Usage Example
nfr_tester = NonFunctionalRequirementTester()

# Test performance requirement
perf_result = nfr_tester.test_performance_requirement('NFR001', 2.0, 1.8)

# Test security requirement
security_checks = [
    {'name': 'Password encryption', 'result': True},
    {'name': 'SQL injection protection', 'result': True},
    {'name': 'XSS protection', 'result': False}
]
sec_result = nfr_tester.test_security_requirement('NFR015', security_checks)
```

### Requirements Quality Metrics
```python
class RequirementsQualityMetrics:
    def __init__(self):
        self.requirements = []
        self.changes = []
    
    def add_requirement(self, req_id, description, complexity, clarity_score):
        self.requirements.append({
            'id': req_id,
            'description': description,
            'complexity': complexity,  # 1-5 scale
            'clarity_score': clarity_score,  # 1-10 scale
            'word_count': len(description.split()),
            'ambiguous_words': self._count_ambiguous_words(description)
        })
    
    def _count_ambiguous_words(self, description):
        ambiguous_words = ['should', 'could', 'might', 'probably', 'usually', 'normally']
        return sum(1 for word in ambiguous_words if word in description.lower())
    
    def track_requirement_change(self, req_id, change_type, reason):
        self.changes.append({
            'requirement_id': req_id,
            'change_type': change_type,  # 'addition', 'modification', 'deletion'
            'reason': reason,
            'timestamp': datetime.now()
        })
    
    def calculate_requirements_stability(self):
        """Calculate requirements stability index"""
        if not self.requirements:
            return 0
        
        total_changes = len(self.changes)
        total_requirements = len(self.requirements)
        
        stability_index = max(0, 100 - (total_changes / total_requirements) * 100)
        return stability_index
    
    def calculate_clarity_index(self):
        """Calculate average clarity score"""
        if not self.requirements:
            return 0
        
        total_clarity = sum(req['clarity_score'] for req in self.requirements)
        return total_clarity / len(self.requirements)
    
    def identify_complex_requirements(self, complexity_threshold=4):
        """Identify requirements that may need more attention"""
        return [req for req in self.requirements if req['complexity'] >= complexity_threshold]
    
    def generate_quality_report(self):
        return {
            'total_requirements': len(self.requirements),
            'stability_index': self.calculate_requirements_stability(),
            'clarity_index': self.calculate_clarity_index(),
            'complex_requirements': len(self.identify_complex_requirements()),
            'change_frequency': len(self.changes) / max(1, len(self.requirements)),
            'ambiguity_rate': sum(req['ambiguous_words'] for req in self.requirements) / max(1, len(self.requirements))
        }

# Usage Example
metrics = RequirementsQualityMetrics()
metrics.add_requirement('FR001', 'User should be able to login', 3, 7)
metrics.add_requirement('FR002', 'System must authenticate users within 2 seconds', 4, 9)
metrics.track_requirement_change('FR001', 'modification', 'Clarification needed')
quality_report = metrics.generate_quality_report()
```

## 🏆 Best Practices and Guidelines

### Requirements Writing Best Practices
1. **Use Clear, Unambiguous Language**
   - Avoid subjective terms (fast, user-friendly, robust)
   - Use specific, measurable criteria
   - Define technical terms and acronyms

2. **Follow Consistent Structure**
   - Use standard templates
   - Maintain consistent formatting
   - Number requirements systematically

3. **Ensure Testability**
   - Write verifiable requirements
   - Include acceptance criteria
   - Define measurement methods

4. **Maintain Traceability**
   - Link requirements to business objectives
   - Track requirement relationships
   - Document requirement sources

5. **Regular Review and Validation**
   - Conduct stakeholder reviews
   - Validate with end users
   - Update based on feedback

```python
class RequirementsPitfalls:
    def __init__(self):
        self.pitfalls = {
            'ambiguous_language': {
                'bad_example': 'System should be fast',
                'good_example': 'System shall respond to user queries within 2 seconds',
                'explanation': 'Avoid subjective terms, use measurable criteria'
            },
            'missing_acceptance_criteria': {
                'bad_example': 'User can search for products',
                'good_example': 'User can search for products by name, category, or price range with results displayed within 3 seconds',
                'explanation': 'Include specific conditions for requirement satisfaction'
            },
            'implementation_details': {
                'bad_example': 'System shall use MySQL database',
                'good_example': 'System shall store and retrieve customer data reliably',
                'explanation': 'Focus on what, not how - avoid constraining design'
            }
        }
    
    def check_requirement_quality(self, requirement_text):
        issues = []
        
        # Check for ambiguous words
        ambiguous_words = ['fast', 'slow', 'user-friendly', 'robust', 'flexible']
        for word in ambiguous_words:
            if word in requirement_text.lower():
                issues.append(f"Ambiguous term detected: '{word}'")
        
        # Check for measurable criteria
        if not any(char.isdigit() for char in requirement_text):
            issues.append("No measurable criteria found")
        
        # Check for implementation details
        tech_terms = ['mysql', 'oracle', 'java', 'python', 'angular']
        for term in tech_terms:
            if term in requirement_text.lower():
                issues.append(f"Implementation detail detected: '{term}'")
        
        return issues
```
