Memory Layout

An array stores elements in contiguous memory locations. This guarantees constant-time access to any element through base-address arithmetic. The trade-off is that insertion and deletion require shifting elements, leading to O(n) cost in the worst case.

Access: O(1) — direct index computation
Search: O(n) — linear scan
Insert (end): O(1) amortized
Insert (middle): O(n) — shift required
Key Insight
Contiguity enables CPU cache prefetching, making array traversal significantly faster than linked-list traversal in practice.

Dynamic Array Implementation

// Dynamic array with geometric resizing (factor 2) class DynamicArray<T> { private data: T[] = []; private length = 0; push(item: T): void { if (this.length === this.data.length) { const newSize = this.data.length === 0 ? 1 : this.data.length * 2; const newData = new Array(newSize); for (let i = 0; i < this.length; i++) { newData[i] = this.data[i]; } this.data = newData; } this.data[this.length] = item; this.length++; } get(index: number): T | undefined { return index < this.length ? this.data[index] : undefined; } }

Address Calculation

For a 1-indexed array with base address B and element size s bytes:

Address(A[i]) = B + (i − 1) × s

Example: int[10] at base address 0x1000 → A[5] at 0x1000 + 4 × 4 = 0x1010

Common Operations

TraversalVisit every element — O(n) time, O(1) space
Insertion (end)Append to last occupied slot — O(1) amortized
Insertion (index)Shift elements right from index — O(n)
DeletionShift elements left to fill gap — O(n)
SearchLinear scan — O(n); binary search on sorted — O(log n)

When to Use Arrays

  • You need fast index-based access to elements
  • The collection size is known ahead of time or grows predictably
  • Memory overhead per element must be minimal (no pointer storage)
  • You frequently iterate over elements (cache-friendly)
  • Insertions and deletions at the ends are the common case

Active Recall

What is the time complexity of inserting an element at index 0 in an array of size n?
Think about what happens to the existing elements
O(n) — every existing element must be shifted one position to the right to make room at index 0.

Quick Check

Which of the following best describes an array's memory layout?

Elements stored in non-contiguous heap-allocated nodes
Elements stored contiguously with index-based addressing
Elements stored in random memory locations linked by pointers
Elements stored in sorted order automatically upon insertion
Answer: Option 2 — contiguous memory with index-based addressing. This is the defining property of arrays.

Summary

  • Arrays store elements in contiguous memory: O(1) access, O(n) insert/delete
  • Dynamic arrays amortize resizing cost to O(1) per append
  • Cache locality makes arrays faster than linked structures for iteration
  • Use arrays when size is stable and index access is the primary operation
